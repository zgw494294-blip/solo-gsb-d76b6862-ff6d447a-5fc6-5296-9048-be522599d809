# 本地赛道计次裁决台

一个完全本地运行的赛道计次（lap counting）裁决工具：录入 1～3 名选手、两段合格耗时区间与至多 40 条感应记录，自动为每名选手选出最优的完整计次方案。

- 后端：Python + FastAPI（`app/`）
- 前端：原生 HTML / CSS / JavaScript，无构建步骤（`static/`）
- 裁决算法：枚举合法趟 + DAG 动态规划（`bisect` 二分前驱），含 400 组随机数据对拍测试

## 裁决规则

每趟从同一选手的感应记录中依次选取 **起点 S → 中途门 M → 终点 F** 各一条：

1. 两段耗时（M−S、F−M）都必须落在录入的**正整数闭区间**内；
2. 同一选手的不同趟**不得共用任何记录**；
3. 后一趟的起点秒数必须**严格晚于**前一趟的终点秒数（`后起点 > 前终点`）；
4. 其余读数一律舍弃，列入“未采纳记录”。

记录可以乱序录入，同一秒允许存在多条记录。

每名选手按以下优先级选择方案：

1. **完整计次数最多**；
2. 计次数相同时，**各趟用时之和最短**（每趟用时 = 终点秒数 − 起点秒数）；
3. 仍相同时，取按计次时间顺序串接的记录 ID 序列**字典序最小**者。

没有任何完整一趟时显示 **0 次**；输入非法时只报错、**不展示任何部分结果**。修改任意输入（耗时区间、选手、感应记录，含增删行与载入示例）后，页面会按当前完整输入**自动重算所有选手**，无需再点按钮；连续编辑会合并为一次重算，“⚖ 裁决 / 重新计算”按钮仍可随时手动触发。输入非法时只显示错误，改回合法值后自动恢复裁决；等待响应期间可继续编辑，只有仍适用于当前输入的响应才会更新结果或错误。

## 比赛名次与罚秒（仅本次页面会话）

每次合法裁决结果上方会出现**比赛名次表**，按选手逐行列出：**名次、选手编号、计次数、原总用时、罚秒（含原因）、调整后用时**。调整后用时 = 原总用时 + 罚秒。

- 有完整计次者按**计次数降序、调整后用时升序**排名；计次数与调整后用时完全相同者**共享名次并跳号**（1、1、3），并列行按**编号升序**展示；
- **零次者排末尾、按编号升序展示且不给名次**（名次列显示“—”），其原总用时为 0、仍可保存罚秒；
- 每名选手可在名次表内保存一个**非负整数罚秒**（默认 0）与一条**至多 200 字的原因**：罚秒必须是十进制非负整数（空、小数、负数等均非法），**罚秒大于 0 时原因不得为空**；校验失败时**保留原已保存的罚秒与原因**不变（未保存的输入文字也不清空，可改后重试）。
- 保存成功后**立即**用最近一次合法结果更新名次，**不向服务器重新裁决**；罚秒**只影响名次表**，不改变采纳记录、各趟/裁决总用时，也不影响人工复核，更不会随 `POST /api/adjudicate` 发送。
- 罚秒仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）：
  - **记录或区间编辑**（增删改无关记录、重排记录行、手动重算等）后，只要编号仍在，罚秒**原样保留**；最新合法结果使用的是**当时已保存**的罚秒；
  - **选手编号改变或选手删除**的当下立即清除对应罚秒——不必等到合法裁决返回，输入非法、防抖合并、请求在途时也一样；之后把编号改回、或补回同编号选手，罚秒**不会恢复**；
  - **“清空”“填入示例”清除全部罚秒**；
- **输入非法或重算期间（含手动“⚖ 裁决 / 重新计算”）名次表隐藏**；过期（含非法）响应不能恢复名次，改回合法值后名次随最新合法结果自动恢复。


## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后浏览器访问：

- **http://localhost:8000**

停止：

```bash
docker compose down
```

## 仅用 Docker（可选）

```bash
docker build -t lap-judge .
docker run --rm -p 8000:8000 lap-judge
```

## 本地直接运行（不使用 Docker）

需要 Python 3.10+：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 **http://localhost:8000** 。

## 页面用法

1. 填写两段合格耗时闭区间（正整数秒）；
2. 添加 1～3 名选手，编号必须互异；
3. 录入感应记录：唯一字符串 ID、选手编号、门（S/M/F）、非负整数秒数；全空行会自动忽略，部分填写视为非法；
4. **无需点击按钮**：修改任意输入（区间、选手、记录，增删行、“填入示例”）后，页面会立即清除旧结果并按当前完整输入自动重算所有选手，结果按选手分卡展示每趟采纳的三条记录与两段/总用时，以及该选手所有未采纳记录；合法结果上方同时展示**比赛名次表**（见下节），可在其中保存各选手罚秒。连续编辑会合并为一次重算；输入非法时只显示错误（名次表也隐藏），改回合法值后自动恢复结果。“⚖ 裁决 / 重新计算”按钮仍可随时手动立即重算。
5. “填入示例”可快速载入一份包含多趟、乱序、舍弃读数的数据（载入后自动重算）；“清空”会同时清除输入、结果、名次、错误与全部罚秒、复核，此前发出的请求随后返回也不会恢复它们。

## 人工复核（仅本次页面会话）

每趟已采纳计次下方都有“人工复核”区：可将该趟标记为 **未复核 / 通过 / 存疑**（默认未复核），并填写至多 **200 字**备注，点击“保存复核”生效。选择“存疑”时备注必须非空；备注超长或存疑无备注会保存失败，并**保留原已保存的复核内容**不变。

- 复核只是人工标注：**不改变**采纳方案、计次数与用时，也不会发送到服务器；
- 复核仅保存在页面内存中，**刷新页面即全部清除**（不写入 localStorage 等任何持久存储）；
- 复核按“选手编号 + 三条记录的 ID/门/秒数 + 该趟两段耗时 + 两段耗时区间”绑定到具体的趟，**不按趟序号或记录行号定位**。每次修改输入都会逐条核对已保存的复核，失效逐趟独立判定，一次编辑不会清空无关趟的复核：
  - **任一绑定值改变**（修改选手编号或两段耗时区间，或修改绑定记录的 ID、门、秒数），或**绑定记录、绑定选手被删除**，对应复核在输入变更的**当下立即丢弃**——不必等到返回合法裁决，即使当前输入非法、尚在防抖合并、或上一次请求仍在途也一样；之后再把值改回（例如下限清空触发非法报错后填回原值，或在防抖提交前改动后立即改回），该趟也只会显示**未复核、空备注**，旧状态与旧备注**不会恢复**；
  - 绑定值未变时（重排记录行、增删或修改无关记录、手动重新计算），只要该趟仍被最新合法裁决采纳，复核**原样保留**；最新合法裁决不再采纳的趟继续清除；过期响应（含非法响应）同样不能恢复已丢弃的复核；
- 输入非法或等待重算期间复核编辑区会隐藏；过期的响应不会覆盖正在编辑的新备注；
- “清空”与“填入示例”会同时清除全部复核记录。

## API

`POST /api/adjudicate`

```json
{
  "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
  "runners": [{"number": 101}, {"number": 102}],
  "records": [
    {"id": "a1", "runner": 101, "gate": "S", "time": 0},
    {"id": "b1", "runner": 101, "gate": "M", "time": 12},
    {"id": "c1", "runner": 101, "gate": "F", "time": 25}
  ]
}
```

- 合法：`200 {"ok": true, "result": {...}}`
- 非法输入：`422 {"ok": false, "error": "中文原因"}`（不返回部分结果）
- 请求体不是 JSON：`400`
